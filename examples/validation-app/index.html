Cognitive3D WebXR SDK — Validation App

Sends real WebXR sessions with real device signals (c3d.device.*) to Cognitive3D, so we can validate how the pipeline classifies each device / browser / headset. Pick a page to run:

inline.html
Desktop or phone browser — no XR. Start here on a laptop or phone. immersive-vr.html

Passthrough-capable headset (or the emulator). Requests an immersive-ar session.

Append ?env=dev (default) or ?env=prod to any page to target the dev or prod backend.

See recorded sessions in the Cognitive3D dashboard: dev · prod

Each session's participant name is set to its type + environment (e.g. VR — macOS · Chrome), so you can scan session types at a glance in the dashboard's Participant column.

No headset? Test with the Immersive Web Emulator

A Chrome extension from Meta that fakes a VR/AR headset, so the immersive pages work on a desktop browser.

  1. Install the Immersive Web Emulator from the Chrome Web Store, then reload this site.
  2. Enable it: open DevTools (F12) and switch to the Immersive Web Emulator tab, then pick a device (e.g. Meta Quest 3). The VR/AR pages will then report support and the Enter button becomes active.
  3. Use it: open immersive-vr or immersive-ar, click Enter, and drag the headset / controllers in the emulator panel to move around.
  4. Exit: pull the emulated controller's trigger to end the session (AR also shows an Exit AR button over the view). The plain Exit button at the top of the page is hidden behind the emulator's overlay while immersed, so use the trigger.
Ending a session by any method (trigger, in-view button, or the emulator's own exit control) ends the Cognitive3D session and sends the c3d.sessionEnd event automatically.
