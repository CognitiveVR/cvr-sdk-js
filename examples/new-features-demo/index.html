Cognitive3D WebXR — New Features Demo

A small three.js + WebXR app that exercises three features added to the SDK: object/plane detection, eye-tracking fixations, and remote variables. It uses the real built SDK (../../lib/c3d.umd.js).

Open the demo →

1. Build the SDK

npm run build   # from the repo root — produces the gitignored lib/

2. Configure

  1. Copy config.example.js to config.js in this folder.
  2. Fill in a DATA-scoped Application API Key and your Scene (Name / ID / Version).
  3. config.js is gitignored — never commit real keys.

3. Serve over localhost (a secure context)

python3 examples/new-features-demo/serve.py 5173   # no-store, avoids stale cached pages
# then open http://127.0.0.1:5173/examples/new-features-demo/demo.html

On a Quest, plug in over USB and run adb reverse tcp:5173 tcp:5173, then open http://127.0.0.1:5173/examples/new-features-demo/demo.html in Quest Browser.

What to look for

  • Object/plane detection: enter AR and walk around your room; the "Planes/Meshes detected" counters rise and "Room data sent" increments. Requires immersive-ar (on Quest, VR reports the feature as enabled but detectedPlanes stays empty) and requires Space Setup on the headset.
  • Fixations: look steadily at the blue cube; "Fixations sent" increments. The "Gaze source" row reads eye tracking on headsets that expose an eye-gaze input source through WebXR (Pico, Galaxy XR, Vive Pro Eye, Varjo, Quest Pro) and head direction everywhere else. Quest 3 has no eye tracking hardware, so it always uses head direction. Fixations are recorded either way.
  • Remote variables: any variables defined for the participant on the dashboard appear in the overlay, resolved by name.
  • Confirm the session (with planes, fixations, and the c3d.remote_variable.* session properties) on the Cognitive3D dashboard.
